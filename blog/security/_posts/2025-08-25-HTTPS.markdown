HTTPS는 암호화 되지 않은 평문 통신인 HTTP에서 암호화 계층이 들어간 통신 방식이다.

그렇다면 암호화 계층의 역사에 대해서 알아보자.

## HTTPS의 암호화 계층

### SSL(Secure Sockets Layer)

넷스케이프(Netscape)가 1990년대에 만든 암호화 통신 프로토콜이며 발전 이력은 아래와 같다

- SSL 1.0 → 공개 안됨

- SSL 2.0 (1995) → 보안 취악점 많음, 폐기

- SSL 3.0 (1996) → 크게 개선, 하지만 현재는 취약점 발견되어 사용 금지

### TLS(Transport Layer Security)

SSL의 후속 표준이며 첫 버전인 TLS 1.0 (1999) → SSL 3.0을 표준화한 버전(IETF가 관리 시작)이다.

발전 이력은 아래와 같다

- TLS 1.1 (2006) → 보안 개선, 현재는 폐기

- TLS 1.2 (2008) → 오랫동안 주류, 아직도 많이 쓰임

- TLS 1.3 (2018) → 최신, 핸드셰이크 간소화 + 보안 강화

## 타임라인

| 연도 | 프로토콜/버전 | 표준(RFC) | 현재 상태 | 핵심 변경점/이슈 |
|:---:|:---:|:---:|:---:|:---:|
| 1995 | SSL 2.0 | - (IETF 표준 아님) → TLS네서 금지 | 사용 금지 | 구조적 결함 다수로 TLS에서 협상 금지(RFC 6176) |
| 1996 | SSL 3.0 | RFC 6101(역사 문서) | 사용 금지 | 설계 결함 + POODLE(2014)로 폐기, 사용 금지(RFC 7568) |
| 1999 | TLS 1.0 | RFC 2246 | 2021년 공식 폐기 | SSL3.0을 표준화. 이후 BEAST(2011, CBC 취약)등으로 퇴출. 2021년 TLS1.0/1.1 폐기(RFC 8996) |
| 2006 | TLS 1.1 | RFC 4346 | 2021년 공식 폐기 | CBC에 명시적 IV 도입 등 개선. 그래도 2021년 함께 폐기(RFC 8996) |
| 2008 | TLS 1.2 | RFC 5246 | 현역(단, 1.3 권장) | AEAD(AES-GCM), 새 PRF(hash) 등 현대 암호 도입. BCP 195(가이드)에서 강력히 권고 |
| 2018 | TLS 1.3 | RFC 8446 | 최신 권장 | 핸드쉐이크 단순화(1-RTT), FS 기본, RSA 키교환/CBC/RC4 제거, 0-RTT(재개) 도입(재생공격 주의) |

## 정리

- SSL은 더 이상 안 쓰이는 옛 프로토콜 (사실상 역사 속으로 사라짐)

- TLS가 현재 유일하게 쓰이는 프로토콜

- 그래서 사람들이 습관적으로 **SSL 인증서**라고 부르지만, 실제로는 TLS 인증서가 맞음
